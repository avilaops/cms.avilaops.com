# Estúdio: plano

Data: 02/11/2026. Spec: `docs/superpowers/specs/2026-11-02-estudio-design.md`.

Cada fase fecha quando o critério dela passa. Fase seguinte não começa em
cima de critério vermelho da anterior.

## Fase 1 — Fatia vertical

Entrega desta mudança.

- Migração `20261102000018_estudio.sql` sobe do zero com o migrador do crate
  `cms-dados`.
- Home do estúdio no painel, com sessão, para quem participa do site.
- Criar arquivo, abrir, aplicar sistema, inserir frame, retângulo e texto,
  mover nó, favoritar.
- Prévia pública pelo token, sem sessão, sem o rascunho posterior.
- Biblioteca `docs` desligável, com as sete peças no canvas.
- Adaptador de geração desligado e configuração que não chama a rede.
- `cargo fmt`, `cargo clippy --workspace --all-targets --features cms-web/contracts --locked -- -D warnings`
  e `cargo test --workspace --features cms-web/contracts --locked`.

Critério de verificação:

- `crates/dados/tests/estudio.rs`: arquivo de um site não aparece no outro; a
  versão não aceita `UPDATE`; republicar mantém o token.
- `crates/web/tests/estudio.rs`: anônimo é mandado ao login; quem não
  participa recebe 404; o canvas grava a cor do sistema Tinta e a largura do
  aplicativo; o retângulo novo não vaza na prévia já publicada; autor não
  publica nem edita arquivo alheio; a chamada da biblioteca `docs` renderiza
  no quadro.
- `crates/dominio` e `cms_integracoes::geracao`: permissão, catálogo, ponto
  do zoom e adaptador desligado.
- O aviso em `crates/web/recursos/biblioteca-docs/AVISO.txt` continua com a
  licença MIT e a revisão do Fumadocs.

## Fase 2 — Geração de telas

- Adaptador HTTP em `cms_integracoes::geracao` que só existe quando a
  configuração é válida. Sem URL, continua o adaptador desligado.
- O `POST` do pedido chama o traço e grava nós. Falha de provedor não apaga
  o arquivo.
- O texto da home deixa de dizer que a geração está na fase seguinte.
- Teste com um servidor HTTP local, sem provedor real e sem segredo no
  repositório.

Critério: um pedido de teste produz nós persistidos; provedor ausente
continua gravando só o arquivo, como na fase 1; nenhuma chamada sai se a
URL não for `https`.

## Fase 3 — Sistemas importados

- Criar sistema do site a partir de um CSS colado, com a mesma lista fechada
  de propriedades que os tokens já aceitam. O que não for cor ou fonte
  conhecida é recusado.
- Tailwind e DESIGN.md só entram se der para reduzir aos mesmos tokens, com
  teste do arquivo de exemplo. Sem isso, continuam fora.
- Importar página por URL continua fora: é captura, não token.

Critério: um CSS mínimo vira um sistema selecionável no arquivo; CSS com
`expression` ou URL externa não grava.

## Fase 4 — Conector para agente de código

- Ferramentas MCP próprias do estúdio, no conector que o CMS já tem, com
  escopo separado do conteúdo.
- Sem plugin de marketplace e sem tela que imite o instalador de outro
  produto. O passo a passo descreve só o que o servidor realmente faz.

Critério: uma chamada autenticada lista arquivos do site da conta e recusa
o site de outra; o teste de contrato cobre sucesso e recusa.

## Fase 5 — Captura e o resto da biblioteca

- Extensão de navegador, se ainda fizer sentido, num repositório que não
  puxe Node para o runtime do CMS. O CMS só recebe o HTML já sanitizado.
- Peças que ficaram de fora do catálogo `docs` (acordeão, código, passos,
  tabela de tipos) e o tema escuro.
- Favorito por conta e mais de uma prancha por arquivo.

Critério: cada peça nova tem nó, prévia e teste de escape. A extensão não
é critério do binário do CMS.
